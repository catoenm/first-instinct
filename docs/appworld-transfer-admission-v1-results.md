# Executions pass; transfer question admission does not

The four reserved payment-workflow representatives that passed the substrate
screen also pass the independently audited branch collection. There were **82
fresh world executions**: 12 reference/replay/collateral controls, 35 alternative
branches and 35 exact independent alternative replays. These cover four underlying
task instances, four programs and eight observed history points, with 3,310
simulated application calls. Every alternative replay is exact; all four injected
collateral changes are detected by direct state inspection.

The primary alternatives include 12 successes (eight redundant reads and four
failed-authentication-then-retry plans) and 23 failures (eight stops, eight omitted
calls, four invalid-session plans and three wrong targets). Outcomes come from
executed assertions and independent state-preservation checks, never model answers.
The [branch audit](../results/appworld-transfer-branches-v1/summary.json) records
counts and artifact hashes. No model was called.

The separately frozen question admission attempt is **rejected**. It produced 90
raw question variants, grouped to 84 unique questions before context admission.
Only 42 candidates fit the unchanged 8,192-token interface, and only one program
retains useful paired decision menus and positive alternatives. The protocol
requires all four, so **zero questions are accepted for evaluation or training**.
Six surviving menus have complete matching forecasts, but that narrow subset is
not substituted for the required transfer coverage.

Two kinds of exclusion explain the gap:

- Four history points fail the existing causal argument check. Unsupported fields
  include direction, date bounds, sort order and amounts. These are provenance
  failures under the current compiler, not evidence that the reference argument
  is necessarily wrong. A transformation or public domain needs an explicit proof.
- Forty-two unique questions exceed the context ceiling even after the current
  lossless record-table encoding. They were rejected rather than cropped.

The [preparation receipt](../results/appworld-transfer-questions-v1/summary.json)
reports every program's retained coverage and the rejected status. Raw candidates,
traces and detailed exclusions remain private. These worlds stay reserved; they
did not influence model updates or checkpoint selection. There is no transfer
performance result and no new inference rental.

An offline follow-up found a preparation gap: the cached public API schemas
covered only the training applications and omitted the reserved payment app.
We captured its 54 public API definitions in a separate artifact. A small parser
now recognizes explicitly documented finite membership values, using literal
parsing rather than executing documentation. Two regression tests ensure that
arbitrary expressions and numerical ranges cannot license a hidden value.
The [metadata review](../results/appworld-transfer-schema-review-v1/summary.json)
shows that direction and sorting restrictions can be grounded this way; date
bounds and calculated amounts remain unsupported. The original failed admission
is unchanged, and the review admits zero new questions.

The next data work should qualify typed argument construction from public API
documentation and observed values, including explicit date and amount operations.
It should also test an evidence interface that preserves the information needed
to choose and forecast while fitting the supported context. Any new compiler or
context strategy needs its own prospective controls, round-trip or sufficiency
checks and honest accounting. Merely admitting hidden reference constants,
discarding necessary evidence or relaxing the four-program gate would invalidate
the comparison. Preserve this failed preparation as evidence of the current limit.
