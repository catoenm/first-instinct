# Prospective release mixture admission

Assemble one private, tokenized corpus using the already qualified sources below.
This stage runs no model or optimizer, executes no new environments and rents no
hardware. Preserve all source files and freezes. Freeze this protocol, assembly
code, tests, source manifests and source data hashes before producing the pack.

Use the pinned Qwen3.5-9B tokenizer/label vocabulary and the original supervised
step-2742 adapter lineage. The release context target is 4,096 complete input
tokens. Existing longer AppWorld questions are rejected whole, never truncated.
The preliminary census found 288 of its 484 training questions fit this bound;
final accounting must come from the frozen assembly, including every rejection.

Admit these sources only in their existing roles:

- Original general corpus: training and known development/regression partitions.
- Qualified release-tool-data-v1: training, development and reserved transfer,
  using its digest-bound loader. These targets remain observed teacher actions.
- Qualified decision-source-registry-v1: the five existing training mechanisms,
  report development, calendar known/exposed transfer and publication diagnostic.
  Preserve distribution targets and their executed source lineage. The source
  index's training-ready=false means a complete learning runtime is a separate
  gate; it must not be relabelled as a completed training run.
- AppWorld supervised-v2: new_forecast/new_decision training only, and its existing
  development forecast/change/decision partitions. Protected contents stay private.
- Newly qualified release-retail-questions-v1: the entire connected component is
  training-only, guarded by its admission and usage hashes.

Do not add telecom to learning. Preserve its corrected evaluation-only manifest.
Do not consume AppWorld payment transfer, calendar, publication or tool reserved
transfer for checkpoint selection or calibration. Export their inherited roles
clearly; known/exposed regression and fresh reserved evidence are different.

Require an explicit target contract per row: acceptable_set for hard/acceptable
actions, or categorical_distribution for outcome probabilities and the retail
protocol's tied-action distributions. Validate finite nonnegative unit-sum
distributions and exact option alignment. Never infer both yes and no to be an
acceptable set from a fractional outcome target. Reuse qualified token sequences
without changing their formatter or option order.

Join exact token-input duplicates only when their role and target contract are
identical, retaining every source reference and underlying group. Stop the pack
if a duplicate conflicts in role or label; do not resolve it by an opportunistic
vote or reassignment. Check inherited source groups across roles independently
of token equality. Related histories or teacher views remain grouped. Report
these exact checks without claiming to detect semantic paraphrases.

Report source rows, rejected rows, unique token questions, underlying source
groups, tokens, and presentation counts separately. The pack starts with zero
training consumption. Source group counts are not independent task counts: for
example, the retail component still contains only three goals and ten physical
states. All original general examples are replay, not newly collected data.

The output is a data pack, not a training-ready declaration. A later prospective
pilot freeze must bind exact source/task weights, sampling or visit schedule,
evaluation cohorts, parent hashes, mixed-objective runtime, context/padding checks,
restart/recovery, retention/advancement gates and remaining compute authorization.
Do not start the rental merely because corpus assembly passes.
