# A development curriculum for command consequences

The 9B reservation baseline and forecast probe exposed development weaknesses.
This data pack teaches a smaller prerequisite: the immediate consequences of a
specified command. It is built from the already published, SQLite-verified
branches. It is **development training data, with no untouched test split**.
It adds event labels and presentations, not independent environments or new
real-world experience. Keep the original 9B diagnostics unchanged.

For each supported public history and first action in the qualified corpus,
read the actual state immediately after that action. Group only identical
public histories, and condition the disclosed prior on the compatible hidden
worlds. Each compatible world contributes once, rather than once per repeated
receipt. Derive exact categorical probabilities for four questions:

1. Is the request empty, partial, or complete?
2. Does the account exist?
3. Is A out of stock?
4. Is B out of stock?

Model inputs contain the initial prior, current public observation and history,
transaction semantics and one specified command. They never contain the
sampled world, private after-state, verifier label, or probability target.
Ask about the state immediately after one command; no repair continuation is
implied. Use the three already defined presentations, including one reversal
and one rewrite. Preserve a shared group ID across all correlated labels and
presentations. These variations are not separate scientific observations.

Before generation, bind source hashes and the exact qualified branch artifact.
Generate at most 3,500 rows and 25 MB. Expected shape: 288 context/action groups
times four event questions times three presentations = 3,456 rows. Record
canonical event count, distinct histories, nondegenerate probability labels,
fraction vocabulary and provenance. Execute no new database or model calls.
Reconstruct every published row from its receipt and recompute all counts.

The intended future loss is soft-target cross entropy over the offered labels:
`-sum(target_probability * log(model_probability))`. The current hard-label
trainer must not silently turn all nonzero-probability answers into an
acceptable-answer set; that would discard the probability information.

This pack is a bounded curriculum prototype. A meaningful next training study
must add new executable mechanisms and new split ownership, then reserve whole
program/fault combinations and independently authored wordings before model
evaluation. Use new stochastic on-policy trajectories for Proximal Policy
Optimization; the published greedy diagnostic trajectories are not on-policy
samples from their recorded softmax distributions. Compare the same warmed
starting checkpoint under reward-only and reward-plus-forecast training, with
equal interaction budgets, retention checks, measured extra label/compute
costs, and a forecast-only control. Evaluate decision return, deterministic
consequence accuracy, and uncertain-event probability error separately.

No training or model improvement is claimed by generating this pack.
