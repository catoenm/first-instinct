# Expanded decision pilot: one bounded comparison

Start every arm from the original supervised step2742 adapter on the pinned
Qwen3.5-9B foundation. Keep the exact original adapter bytes and initial trainable
tensor hash. No larger model, extra supervised warm-up or later selected adapter
is introduced. This extends the completed evidence-decisions-v2 and mixed-decisions-v1
studies; their data, sources and checkpoints remain frozen.

Train on five mechanisms: configuration changes, database repair, ToolSandbox
application delivery, filesystem mutation scope and reservation transactions.
Use the qualified source index's 2,280 unique forecast inputs and exact uncertain
targets. Report generation remains the whole development mechanism for checkpoint
selection. The complete calendar mechanism is the new reserved transfer test;
publication is exposed diagnostic data and is excluded from this learning pack.
No related world, goal, fee, trajectory or wording variant crosses those roles.

Compare forecast-only, reward-only Proximal Policy Optimization and combined
learning at seeds 1507 and 1609. General replay is present in all three arms.
Every language start is identical. Each seed has a frozen input-only schedule:
six live episodes per training mechanism per update, four unique forecast inputs
per mechanism and 16 general replay questions. Reward-bearing arms consume fresh
on-policy trajectories; forecast-bearing arms consume the same preexecuted
probability targets. A forecast-only arm has no live training interactions.
Balanced episode counts do not imply equal transitions, which are counted from
actual executions. Within the forecast objective, each mechanism and then its
four chosen inputs have equal weight; source multiplicities are provenance, not
extra loss weight. Save every sampled action probability, actual tool result and
verifier receipt. Repeated presentations are not new tasks.

Each arm is capped at 40 updates, one optimizer pass per fresh batch, using
language/critic learning rates 0.000001/0.0001. Forecast weight is 0.2, replay
weight 0.5, value weight 0.5, entropy weight 0.01 and policy clip 0.2. The
[prospective weighting rationale and mechanics](expanded-learning-v1-protocol.md)
use previous training-gradient evidence, not calendar results. Record new initial
component gradients and alignment without adapting this recipe from test scores.

Sample actions with the declared 80% model/20% uniform behavior mixture and
rescore the same distribution in the policy loss. Forecasts stay native. Before
and after each attempt check both native action probabilities and the behavior
mixture on a fixed set of 20 training-only guard inputs plus the current rollout
inputs. Require mean divergence <=0.02 and maximum input divergence <=0.10 for
both. Reject and restore excessive or nonfinite updates, retain their presentation
counts, stop the arm and never select its rejected parameters. The value head
is detached from language gradients.

Measure report-development return, forecast expected Brier and general retention
before learning and every ten accepted updates. Eligible checkpoints must keep
general macro accuracy within 0.02 and macro log loss within 0.05 of that arm's
unchanged start, and report return/Brier within 0.02. Among eligible checkpoints,
select improvements exceeding 0.0001 in `return - 0.25 * expected_brier`; otherwise
keep the original. Stop on a safety failure or two non-improving evaluations after
at least 20 updates. Preserve best and latest separately. Stop checks and selection
never use calendar scores.
Skip an arm as having insufficient development headroom if the unchanged model
is within 0.02 return of the declared public report controller and its excess
forecast Brier error is already below 0.01.

Once selected, evaluate each checkpoint on all 80 calendar cases and the 576
unique calendar forecast inputs, alongside the unchanged original control.
Report structures, regimes, uncertain versus deterministic forecasts, incorrect
mutations and costs separately. Average calendar episode return first within

two fold-occurrence goals from silently doubling that structure's weight. Average
forecast scores first within each structure and then equally. Keep question
lineage sufficient to recover each structure. Also report raw case-weighted
results for auditability. General transfer uses the unchanged 1,128-question pool;
retention uses 622 and replay uses the unchanged 4,096-question pool.
