# Paired data admitted; the longer cloud experiment is starting

The next local data stages are complete. The 4,721-question paired curriculum
now has explicit repair effects, checked training ownership and a supervised
loss consumer connected to guarded updates with general replay. The original
9B supervised checkpoint remains selected. The bounded trainer and portable
cloud entry are now qualified, and one H200 has been allocated. At this update,
bootstrap is underway and no new optimizer update has been observed. See the
[launch record](paired-capacity-v1-launch.md) for the current phase; the earlier
readiness aggregate remains a dated preparation snapshot.

## Inputs now describe what the tools actually do

A separate overlay augments 704 configuration/database questions, covering 616
forecasts, 88 decision or inspection questions and 80 uncertain forecasts.
It explains the selected target's actual update, failed writes, inspection
outages, prerequisites, costs and terminal rules. It never supplies the correct
hidden target or changes a continuation.

Read-only checks reconstructed 1,512 existing execution branches, 2,600 actor
transitions and 3,872 command presentations. They checked the actual selected
target's effect even when that target was wrong for the goal, plus preservation
of other files/rows, summary measurements and control flags. All 2,244 affected
cyclic presentations retain their original labels. The longest augmented input
is 1,325 tokens; no input is truncated. The previous source files stay unchanged.

Eight effect-contract tests passed. The guarded preparation took 6.3 seconds,
peaked below 982 MB and added no swap. An earlier attempt used the system Python
without the tokenizer dependency and stopped before creating any data; rerunning
with the existing project environment succeeded without a source change.

## Admission keeps related data together

Admission scanned 867,256 stored presentations in 27 files. It checked original
and augmented inputs, old group aliases, receipt lineage and release-mixture
namespaces. There were zero candidate token or related-group matches in the
protected development, retention and reserved sources. Reserved model scores
remain unopened. This is an ownership check, not evidence of semantic novelty.

Expected matches to earlier training pools remain explicit. The competing-writer
panel is an exercised, training-owned diagnostic; its source role is retained
when admitting it for training. It is not a held-out transfer set. Counts of
matching pool rows do not measure previous optimizer consumption; the
[completed experiment report](oracle-capacity-probe-v2-results.md) records that
separately.

The admitted package has 14,313 position presentations: 2,992 acceptable-choice
targets, 144 decision-preference targets and 11,177 outcome distributions. These
are still the same 4,721 canonical questions, with no new worlds or executions.
A private usage receipt binds every staged row to its full hash. Five admission
tests passed; the full scan took 28.3 seconds, peaked below 645 MB and added no
swap.

## The loss consumer keeps the distinctions intact

Acceptable sets optimize their combined probability. Verified outcome
distributions optimize their actual probability mass. Retail preference
distributions retain a separate semantic type. They are not outcome confidence.
All targets and private metadata stay outside the model-forward rows.

Seven CPU tests checked uncertain optima, tied choices, permutation-invariant
loss/gradients, changed-data rejection and language-only gradient routing. All
14,313 actual admitted presentations passed the usage and target-interface
checks. That check used bounded score tensors, without model weights or an
optimizer. Four additional tests exercised the actual guarded update with small
synthetic networks, including general replay, forecast-only operation and exact
restoration of weights, optimizer and random state after a rejected step.
Those synthetic tests are not 9B training or performance results.

questions. Initial decisions and inspection-value questions appear in every
