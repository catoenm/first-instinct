# Complete the missing evaluations before more learning

The previous capacity pilot preserved two final adapters without completing their
evaluation: reward learning after 28 accepted updates, and the combined arm after
16 supervised plus 15 reward updates. Their `latest` folders contain earlier
step-16 adapters. This protocol measures the `interrupted` final adapters with
their matching saved critics. It authorizes no additional training or GPU rental.

Prepare a portable, hash-bound input manifest from the recovered and independently
audited run. Bind the original foundation revision, data freeze, source hashes,
accepted update, adapter file hash, adapter tensor hash and critic file hash.
Refuse an incorrect folder, step, adapter or manifest before loading the model.
Recheck actual loaded tensor identity and unchanged language/critic weights after
evaluation. There is no optimizer or backward call.

For each checkpoint, use the exact earlier contracts and cohorts: 2,064 canonical
and 2,064 reversed panel questions, all 12 paired database episodes, 36 report
decisions, 308 report forecasts and 622 general retention questions. Use the
existing canonical action forward, including its gradient-capable execution
mode, with no parameter updates. Load the existing saved critic for consistent
receipt lineage; it does not select greedy actions. Keep native action scores
separate from forecast probabilities. Execute database/report actions and verify
their results as before. Reserved release scores remain closed.

The new evaluator checks its deadline between retention batches as well as the
other evaluation stages. Record each completed stage and preserve partial files.
Write final aggregate metrics and a complete receipt only after exact coverage
and unchanged-weight checks pass. A timeout, missing cohort or cleanup failure
cannot be presented as a complete measurement. Report the trained update and
evaluated update explicitly; these adapters contain unequal learning doses.

For a future training controller, allocate separate training, final-evaluation
and recovery windows. Do not start another training step when its bounded cost
would reach the training cutoff. Reaching that cutoff must leave evaluation and
recovery available. Reaching the evaluation deadline must preserve incomplete
status and the recovery window. The completed pilot's runner remains immutable.
Local synthetic-clock and interruption tests exercise these boundaries without
loading a foundation model.

The proposed evaluation entry point defaults to a 20-minute ceiling per
checkpoint, including model loading, and refuses a ceiling above 30 minutes.
A future allocation still needs a separately bounded provider shutdown and
verified artifact collector; this entry point does not create or manage cloud
resources. Local qualification establishes input integrity and controller
behavior, not actual CUDA success. No foundation inference runs on the Mac.

The original supervised model stays selected. These measurements complete an
exposed, training-owned diagnostic; they cannot establish fresh transfer or
promote a release. Any later compute must remain inside the original cumulative
authorization after fresh billing reconciliation, with all existing holds retained.
