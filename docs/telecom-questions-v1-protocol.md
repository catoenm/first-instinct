# Admit paired questions from the qualified hidden-cause collection

This is a local, offline admission stage. Reuse the completed 144 telecom world
receipts; do not execute another world, query a model, rent hardware or change
their frozen sources. No official benchmark tasks enter the process.

Build at most 54 raw questions from the three original visible histories:
six alternatives times two forecast horizons, three inspection-cost decision
questions, and three inspection-value questions for each mechanism. Keep exact
duplicate rendered questions once, merge their witness sets, and reject conflicting
targets. Report raw variants, unique questions, compatible configurations, physical
states and actual training consumption separately. Do not count a replica as
another world in the prior.

Preserve original ownership: device switches are training candidates, roaming is
development only, and the entire allowance mechanism is reserved for transfer.
Related costs, wording, trajectories and hidden configurations cannot cross those
boundaries. Require all three mechanisms and all three question categories; do not
silently drop a difficult family or relax a token cap until admission passes.

## Displayed input and execution meaning

Keep the native initial lookup response and original public task contract exactly.
Bind customer and line identifiers only from that lookup. The declared tariff is
part of the original visible task. Never put hidden configurations, private state,
verifier probes, receipt names, split labels, outcomes or aggregate probabilities
in the model input.

Display each offered continuation as a short, self-contained Python procedure,
using only `call(tool_name, arguments)`, public arguments and returned responses.
This is a familiar program representation, not a claim that a model will interpret
it correctly. `call` returns the original public response text, or the one explicitly
documented error object for an invalid zero-gigabyte purchase. JSON parsing and
decimal arithmetic have their normal Python meaning. There is no hidden repair
helper or unstated retry policy. Do not execute arbitrary input or model-generated
code: only the compiler's fixed, hash-frozen programs are eligible for the offline
trace interpreter.

Prove that every displayed procedure, when replayed with each receipt's actual
public responses, requests exactly its executed commands in the same order, with
the same arguments, and then stops. Check all four compatible worlds and both
independent replicas. Immediate forecasts display only the first attempted command
and then stop; stopping has no command. Continued forecasts display the whole
procedure. Do not infer a continued label from an immediate observation.

The decision asks which offered procedure maximizes expected terminal utility
under the same visible history and prior. The observation-value question asks
whether the specified inspect/repair procedure strictly beats the best offered
blind/stop alternative after costs. These are finite-menu comparisons under the
declared continuation, not unrestricted optimal planning or a hidden-state oracle.
Keep menu order fixed across a mechanism's cost variants and choose that order
independently of outcomes.

## Targets, joins and admission checks

Recompute forecast probabilities from independently verified executed outcomes,
weighting the four compatible worlds equally. Retain fractional distributions;
never replace them with majority labels or an acceptable set containing both
answers. Decision and observation-value targets come from expected utilities,
averaging worlds before maximizing. Preserve all attempted actor-call costs and
actual billed changes; exclude sunk lookup and private verifier calls.

Every admitted forecast requires four distinct world witnesses and their exact
replays. Each decision menu and observation-value comparison must join the
appropriate continued forecasts from the identical public evidence. Keep exact
program and first-command hashes in private provenance. A future learning run
must consume these targets using a proper categorical loss; it must not route
fractional rows through acceptable-answer-set loss.

Use the existing pinned Qwen3.5-9B tokenizer locally, with the current serving
message template and a **4,096-token maximum**. No truncation, evidence removal,
model download or inference is allowed. Validate single-token option labels and
re-encode every admitted input exactly. Preserve source, receipt and tokenizer
identity hashes. This changes no model weights and does not create a new training
budget or permission to rent before the wider curriculum is qualified.

Require negative checks for altered displayed commands, hidden-input fields,
duplicate prior weight, swapped outcomes/costs, wrong horizon and wrong ownership.
Test that the existing proper categorical loss distinguishes a fractional target
from certainty and has its minimum at the supplied distribution. Publish only
generic code, aggregate counts and hashes; keep raw questions and receipts private.
