# Live decisions over competing database updates

Keep the qualified executor and earlier fixed-procedure questions unchanged.
This new adapter asks the actor to choose again after each nonterminal tool result.
The actor gets the complete public tool contract, goal, observed history, cached
values, remaining horizon, and costs. It does not receive the hidden writer
schedule, future states, target labels, or verifier result. Order the same six
commands using public state only. No dynamic command proposer is evaluated here.

Execute the selected command in the real SQLite world. Only the independent
terminal state verifier determines the outcome payout. Charge every command,
including errors and refused writes. Normalize raw rewards by 100 for the shared
critic units; this does not change utilities or their ordering. Store the exact
selected-action probability and critic value separately from earned reward.
Never train on the qualification's scripted action records as on-policy data.

Locally qualify the complete four-decision action tree, including redundant
inspection, repeated refusal, recovery, premature stopping, damage, and horizon
exhaustion. The prospective limits are 3,000 database resets, 12,000 actor turns,
4,000 distinct forecast questions, and 4,096 full Qwen tokens per question.
Use each of the two hidden writer schedules, two goals, and three fee profiles.
Each terminal action sequence has one primary execution and one exact replay.
Qualification callbacks are scripts that exercise paths, not a model or measured
decision policy. They do not establish intelligent behavior.

Build a counterfactual index from actual primary executions. At each identical
public history, require all six actions to have been executed in every compatible
hidden world. Deduplicate repeated prefixes by world/history/action, verify exact
event agreement, and condition the declared equal world prior on observed history.
Ask immediate goal status and immediate return code separately. Do not claim these
labels predict a learned continuation. Keep legitimate fractional distributions.
Replays add no probability mass. Verify distributions independently from recorded
database snapshots and command responses, including after evidence resolves the
initial ambiguity. Encode complete prompts without cropping.

This adds reachable trajectories, not new mechanisms: retain the same single
training ownership group, two physical post-schedule states and four world/goal
tasks. Report resets, actor actions, SQL statements, contexts, candidate questions,
replays, model calls, and actual optimizer presentations separately. New forecasts
remain candidates until admitted; this stage does not modify older training packs.

Use the local process/memory guard. No foundation model loading or paid compute
is needed. Preserve failed attempts. Before a new training comparison, separately
qualify the model-policy adapter, immediate-forecast loss, rollout likelihoods,
rollback, mixed replay, fresh transfer ownership, and bounded GPU execution plan.
