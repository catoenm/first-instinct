# Bounded mixed-mechanism learning pilot

Run one 9B diagnostic with the original supervised step-2742 adapter. Keep all
earlier runs immutable. This stage integrates qualified components rather than
repeating their local execution collections. It is not a production release.

Training combines five existing shell/application mechanisms, existing retail
workflows and the qualified revisioned database actor. The forecast pool adds
3,096 immediate-history distributions and 48 displayed-procedure forecasts to
the existing 2,510 verified forecasts. Omit the earlier 72 overlapping initial-state
forecast variants and 18 acceptable-comparison questions from this loss. New
inputs must pass exact-token/ownership admission against the existing packs,
including reserved token fingerprints only. Keep each mechanism's ownership.

At each update collect one fresh episode per shell family, two retail resets and
both database hidden worlds for one matched goal/cost pair. Each reward arm gets
its own current-policy actions and verified rewards. The two database worlds
are paired; retail uses a declared prefix of the existing shuffled block, not a
claim of complete balanced coverage. Use two forecasts per mechanism and 32
general replay questions. Exogenous schedules match across objective arms.

Compare forecast-only, reward-only Proximal Policy Optimization and combined
objectives at paired seeds 20260924 and 20260925. Reverse arm order for the second
seed. Start every arm from identical adapter weights and a zero critic. Use at
most 16 updates, evaluations at 4/8/12/16, and stop after two checks without joint
improvement once eight updates have been attempted. Each arm is capped at 27
minutes including loading/evaluation. A deadline preserves the partial result
and allows the other planned arms to run if their time and recovery allowances fit.
An unexpected implementation failure stops the pipeline. Do not retry a rejected
update or increase the cap after seeing results.

Retain learning rate 0.0000002 for language adapters and 0.0001 for the detached
critic; mean/native-or-behavior divergence limit 0.02 and maximum individual 0.10.
Other objective weights, reward units and clipping match the qualified consumer.
No action labels substitute for live earned rewards.

Development uses the exposed report mechanism: 36 actual decision cases and 308
qualified forecasts with the complete public tool contract. Apply that same
public contract to live report actor inputs through an explicit tokenizer wrapper,
retain the transformation identity, and check exact encoded inputs in receipts.
Other mechanisms are unchanged. Compare each arm with its own unchanged baseline;
do not compare these new input conditions as if they were old-run training gains.
General retention remains the existing 622-question cohort.

The original joint gate is unchanged: at least 0.03 development return gain and
0.02 lower expected Brier error, while general macro accuracy drops by at most
0.01 and log loss increases by at most 0.02. Stop an arm on a return decline over
0.02, forecast Brier increase over 0.02, or either general retention failure.
No release promotion follows improvement on this exposed mechanism alone. Keep
reserved TOUCAN/telecom model scores closed; broader unfamiliar-task evaluation
requires a separately eligible candidate and selection protocol.

Before optimizer work, check the actual CUDA model's current-policy likelihoods,
native/behavior distributions, actor/forecast/value gradients and unchanged
parameters. Check both the foundation and original supervised forecast controls
without training; record control use separately. Reuse pinned isolated workers
and run their Linux parity checks. Local checks use only tokenizers and tiny CPU
fixtures under the existing memory guard.

Use one H200, maximum 5.4 dollars/hour, with a five-hour independent provider-side
stop deadline. Reserve 30 dollars from the existing remaining authorization:
27 dollars maximum compute plus three dollars for storage and recovery. Reconcile
fresh billing and rates before allocation. No new budget, unattended extension,
second rental, or larger model is authorized by this protocol. Recover and hash
check artifacts before retiring the owned pod; the remote stop guard works even
when the laptop disconnects. Preserve rejected and interrupted work in accounting.
