# Prospective admission of paired retail questions

Reuse the completed retail-evidence-v1 witnesses and retail-live-v1 qualification.
Do not execute new worlds, call a model, collect benchmark tasks or train in this
stage. Freeze new admission code, this protocol, source audits/receipts and pinned
tokenizer identity before generating the candidate corpus. Preserve failures.

Prepare a maximum of 72 authored question variants: three goal contracts, each
with six immediate forecasts, six forecasts under an explicitly displayed
continuation, six cost-dependent procedure decisions and six observation-value
questions. Collapse exact duplicate visible inputs while retaining every source
witness. Distinct goals, physical states, executed branches, questions and repeated
presentations remain separate counts. These rows add zero new independent tasks.

Use the same real cached history, goal, prior and public identifier bindings for
paired questions. Each displayed procedure must be self-contained and reproducible
from public responses. Replay it against every saved primary and independent trace;
require the same complete attempted-command sequence, arguments and responses.
Reject unrecognized executable text rather than executing arbitrary received code.
Immediate forecasts stop after the first attempted command (or stop immediately),
including a refused command. Continued forecasts follow only the entire displayed
procedure. Do not silently substitute a learned future policy or promise a fixed
continuation while training a freely acting policy.

Forecast targets are the empirical fractions over the declared equally likely
compatible worlds: eight for each address goal, four for payment. Retain fractional
targets as categorical distributions with proper probability loss, never as a set
of acceptable answers. No model supplies labels. Targets require exact goal,
unchanged-frame and monetary verification from the existing receipts.

Use all six frozen read/write cost pairs. Decision targets maximize expected
terminal reward minus actual actor-attempt fees, averaging worlds before choosing.
Charge failures and redundant reads; exclude sunk cache/background/verifier work.
Observation value asks whether the offered inspection procedure strictly exceeds
the best of the displayed blind-or-stop procedures. Show that comparison set and
costs explicitly; do not claim the result is value under every possible policy.
Check every decision/observation target against the same underlying forecast and
command-count witnesses. Ties, if any, receive explicit uniform tied-action targets.

Keep the entire retail mechanism component, including both address goals, payment
variants and earlier ledger fixtures, in one training-candidate group. Independently
check exact physical-state, full-trajectory, visible-input and token-input overlap
against existing development/reserved sources, including the corrected telecom
usage manifest. Never move a development/transfer mechanism into learning to solve
an overlap. Original role fields alone are not usage authorization. Issue a
digest-bound admission/usage manifest before a loader can consume any candidate.

Use the existing pinned Qwen3.5-9B tokenizer and full constrained-answer rendering.
Reject inputs over 4,096 tokens; never crop away history, alternatives or scope.
Report any rejection and require complete compatible-world coverage. Structural
token checks do not establish model understanding or format invariance.

Require negative checks for hidden truth, incorrect probabilities, horizon swaps,
cost omissions, broken witness lineage, display/trace mismatch and forbidden usage.
Exercise proper distribution loss only with tiny local tensors; this is not a model
or optimizer run. No GPU rental follows automatically from question admission.
The live integration, common training schedules, general replay, evaluation roles,
recovery/budget limits and controlled comparison gates must also be qualified first.
