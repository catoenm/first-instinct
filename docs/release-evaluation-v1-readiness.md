# An independent comparison is prepared, with scores still unopened

The release evaluation now has a frozen data pack, an independent saved-data audit,
and a scorer that requires a development-selected qualifying checkpoint. No model
has scored this cohort. Preparation does not authorize another rental or promote
the current training run.

| Cohort | Original questions | Reversed-option presentations | Meaning |
| --- | ---: | ---: | --- |
| Reserved TOUCAN tools | 2,431 | 2,431 | Demonstrated first-tool agreement; 2,330 requests and 38 server groups |
| Reserved telecom workflows | 34 | 34 | Verified consequences, procedure choice and observation value |
| **Total** | **2,465** | **2,465** | **4,930 presentations of the same 2,465 questions** |

All reversed presentations fit the full 4,096-token limit. Neither order drops
evidence. A scan of 395,966 training/development presentations found no exact
token overlap. This is an exact-input check, not proof of semantic independence
or absence from the foundation's pretraining.

The telecom set contains ten immediate forecasts, twelve forecasts under stated
continuations, six procedure choices and six observation-value questions. Its two
related families share **one connected physical-world ownership component**. It is
a small diagnostic, not 34 independent tasks or the official conversational
benchmark. Its original proposed training role was rejected before any learning;
the corrected evaluation-only ownership remains mandatory.

The independent auditor rebuilt every complete presentation and label from its
admitted source. It separately recomputed procedure utilities from primary world
receipts, verified outcomes, attempted-action fees and actual bill changes. Replay
copies did not add prior probability mass. A tie among good procedures remains an
acceptable-answer set; it is not mislabeled as uncertainty about success.

Seven CPU tests cover label/utility alignment under reversal, source-role
preservation, irreducible forecast uncertainty, decision ties, exact prediction
coverage, answer-order comparisons, server weighting and refusal of an
unqualified candidate. The same tests passed on an isolated exact input/code
archive, including the scorer's dependency closure. Local preparation peaked at
about 0.95 GiB resident memory and the audit at 0.81 GiB; neither added system swap.
No local foundation model was loaded and no new world was executed.

Once a candidate qualifies on development, the selector will seal its exact
weights alongside the original adapted model and unchanged Qwen foundation before
any reserved scores are opened. The evaluation will report first-tool agreement
separately from executed consequence scores and expected procedure utility. It
will also report confidence-bin counts and sensitivity to answer order. No
temperature fitting, checkpoint search or prompt tuning uses this cohort.

If the pilot fails, preserve this unscored pack. Its protocol cannot turn a failed
development checkpoint into a release candidate. This evaluation also does not
establish ordered-score quality, interactive-agent performance, latency or public
serving readiness; those remain separate requirements.
