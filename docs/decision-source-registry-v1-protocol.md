# Cross-mechanism source registry: preparation, not a training run

Build on the completed evidence-decisions-v2 and mixed-decisions-v1 work without
changing their sources, results or checkpoints. Audit and index existing executed
corpora; do not execute new task branches, run a model or rent hardware. Bound
preparation to 15,000 source questions, 6,000 distinct forecast inputs and 150 MB
of output. Failure leaves a rejection record rather than an accepted partial pack.

Prospective source ownership is whole-mechanism:

| Mechanism | Role in the next comparison |
| --- | --- |
| Configuration, database repair, application delivery | Training candidates; already exposed |
| Filesystem mutation scope | Training candidate; newly qualified |
| Reservation transactions | Training candidate; existing development data |
| Report generation | Development/checkpoint selection; already exposed |
| Calendar | Reserved transfer; no model evaluation yet |
| Publication, including intermediate histories | Exposed diagnostic only |

Preserve the original roles in provenance. This registry does not authorize a
row-wise re-split. All related worlds, goals, costs, trajectories and wording
variants stay with their mechanism. Calendar model scores remain unopened until
the learning recipe and selection rule are frozen. The publication diagnostic
must not become an untouched test merely because it acquired more questions.

Use the accepted ToolSandbox application replay collection, never its rejected
predecessor. Run each source's independent offline auditor and validate frozen
source/artifact hashes. Require recorded Linux parity for the new filesystem and
calendar mechanisms. Reconstruct the existing reservation probabilities from the
published actual SQLite branches; do not execute the old study again or initialize
from its later adapter.

For forecasts only, group exactly identical model-rendered inputs. Preserve the
source members, original question identifiers, executed receipt references and
target mass. Uniform-world one-outcome rows become their empirical categorical
distribution. These sources explicitly declare equal priors over their concrete
worlds. Reservation rows already contain exact prior-weighted probabilities;
require identical targets when collapsing duplicate rendered inputs. Use its
original presentation once; count the reversed/reworded presentations separately
as available data, not additional independent events. No argmax conversion or
acceptable-answer-set conversion is allowed. This is proper soft-target cross
entropy data, distinct from next-action questions with several equally good
answers. Keep those decision/value questions in their source corpora.

Report source rows, canonical identities, rendered input identities, executed
branch references, uncertain input groups and repeated presentations separately.
Do not sum incompatible source counters into a claim about independent tasks.
This index performs zero new executions and consumes zero training questions.
Collapsing inputs does not settle future sampling weights: the learning protocol
must specify equal-mechanism sampling and whether multiplicity weights are used.

Tokenize with the pinned 9B tokenizer without truncation. Check collisions across
whole-mechanism roles using actual token sequences, and separately compare with
the unchanged general replay, retention and general transfer pools inherited from
evidence-decisions-v2. Private worlds, outcomes, labels, receipt metadata and split
identifiers must remain outside model-rendered messages. A rendering collision
between distinct mechanisms is an error requiring review, not an automatic merge.

Require CPU tests that reject malformed probability mass, conflicting soft labels,
mixed target semantics and cross-role/cross-mechanism collisions. Verify that
renaming invisible option identifiers does not evade deduplication. Check the
soft cross-entropy identity against repeated one-outcome supervision, including
its gradients. Retain provenance at serialization and audit exact conservation of
source members. This registry is not a qualified live learner; new environment
adapters, their replay parity, proper losses, local update mechanics, a frozen
bounded learning protocol and billing reconciliation still precede any rental.
