## Learning sequence and advancement

1. **Qualify the revised supervised pack and update recipe.** Admit the later
   behavior examples only after their audit and cap contribution per underlying
   request/server. Mix them with general replay and properly labeled outcomes.
   Start from original supervised step 2,742. Retain the forecast-improved
   update-160 adapter as an experimental comparator, not a promoted parent.
   The change must explicitly address the observed general-performance decline:
   report component gradients, evaluate retention early and use prospective,
   guarded step sizes. Do not solve the decline by dropping difficult tasks.
2. **Freeze one bounded supervised pilot.** Fix exact data, schedule, weights,
   learning rate, checkpoint cadence, restore/restart checks, transfer ownership,
   rental deadline and recovery before renting. Preserve the existing release
   gate: at least +3 percentage points in tool macro accuracy; general accuracy
   drop at most 1 point and log-loss increase at most 0.02; no declared product
   slice loses more than 3 points; both proper probability scores must not worsen
   in any declared outcome group. Stop numerical/retention failure and two
   checks without an eligible improvement. A failed pilot does not unlock a
   longer run. These prospective settings are not yet frozen by this roadmap.
3. **Compare learning from real trajectories.** From the same qualified parent,
   compare forecast supervision, reward-only Proximal Policy Optimization and
   their combination with matched replay and two paired seeds. Before launch,
   qualify fresh actor rollouts, action log probabilities, critic separation,
   real reward accounting, context limits and rollback of both parameters and
   optimizer state after an over-limit update. Keep whole mechanisms reserved.
   Preserve the joint transfer requirement: +0.03 verified return and -0.02
   expected Brier error in both seeds, together with general retention. If no
   supervised upgrade qualifies, a separately frozen diagnostic may use the
   original released parent; it is not an automatic production run.
4. **Release only what is supported.** Package the selected model, user-defined
   typed interface and an honest model card. Measure held-out accuracy, proper
   probability scores and reliability-bin counts. Evaluate changed options,
   user rules, stale evidence and unfamiliar mechanisms. A known development
   improvement is not arbitrary-question calibration. Qualify request bounds,
   latency and shared-state question independence before public serving.
