# Keep shared physical worlds out of different learning roles

The first question-admission pass proved labels, displayed programs, joins and
token lengths, but its ownership check was incomplete: it compared mechanism
names without connecting identical physical states or execution trajectories.
The original instruction required related worlds to stay together. Preserve that
pass and its frozen code as an incomplete check; do not use its candidate training
partition for learning.

The subsequent exact-state review found two initial physical states shared by
the device and allowance mechanisms, plus seven identical executed branch traces.
All questions are distinct because their task contracts and priors differ, but
distinct rendered text is insufficient evidence of split independence. No model
has consumed or scored these questions, so this was caught before training or
model-based selection.

Apply the following conservative correction before any use:

1. Connect entire mechanisms whenever they share a complete physical initial
   state or a complete public-command trajectory with the same initial/final
   states. Exclude replay copies from overlap counts. Do not use targets or model
   scores to choose these components.
2. Give a connected component its most restrictive prior role: reserved transfer
   takes precedence over development, which takes precedence over training.
   Never move an evaluation mechanism into training to resolve an overlap.
3. Keep original source ownership immutable in raw receipts and candidate rows.
   Write a separate required-use manifest and new reviewed partitions. Every
   future loader must check that manifest, row identity and intended use.

This assigns **both device and allowance to reserved transfer**, and keeps roaming
in development. It leaves **zero training-eligible telecom questions**. The 51
prepared questions remain useful as short, verified evaluation data: 34 reserved
transfer and 17 development. There is no row deletion, prior change, synthetic
identifier substitution or favorable-score selection to make this pass.

The correction diagnoses an audit gap, not model failure. No new execution or
model call is needed. Keep the earlier preparation report visible alongside the
corrected usage manifest, and report zero actual training consumption. Broader,
independently grouped training workflows must be qualified separately.
