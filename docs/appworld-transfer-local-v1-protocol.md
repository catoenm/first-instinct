# Reserved application transfer: local qualification first

This stage follows the running, frozen AppWorld supervised v2 pilot. It does not
modify that run, its data, its selection rule, its provider deadline or its budget.
All seven upstream training programs involving the simulated payment application
have been reserved since the original inventory. They remain transfer-only.
Upstream development and test files remain unopened. No training, model inference,
paid service or hardware rental is part of this local qualification.

Before opening task contents, select one representative from each of the seven
programs using training metadata only: fewest recorded reference calls, then task
identifier. Do not replace a failing representative with another instance. The
selected representatives require at most 61 reference calls according to metadata.
Keep all three related instances in the same transfer partition, even though this
qualification executes only one. Freeze task files, base databases, installed
upstream sources, execution code and this protocol before the first execution.

Execute a no-op, reference solution and independent reference replay in separate
local processes and fresh worlds for each representative: at most 21 world
attempts. Each world allows one interaction, at most 96 simulated application
calls and 90 seconds inside the environment, with a 120-second process timeout.
Allow at most 2,016 calls over the collection. Block outgoing socket connections
and exclude inherited service credentials. These are local simulated operations.
Reference solutions are permitted solely to qualify the substrate; they are not
actor proposals or model predictions.

Use the existing strict evaluator wrapper: only assertion failures are ordinary
negative outcomes. Other exceptions propagate and quarantine the entire program.
Require nonempty complete assertion accounting, clean no-op failure with unchanged
database files, successful reference and replay, equal initial states, and exact
replayed final database hashes, call counts, request-log hashes and assertion
results. Preserve exceptions and failed attempts; never turn them into labels.
Report all seven candidates and every exclusion. Passing this screen establishes
only a usable execution substrate, not a qualified transfer question set.

A subsequent, separately frozen collection still needs wrong-target and
collateral-change controls, successful recovery alternatives, public-information
argument closure, independent branch replays, token admission without truncation,
and explicit immediate-versus-continuation forecast semantics. It must retain at
least four of the seven reserved programs with useful nonempty decision menus
before renting hardware for this transfer comparison. If that gate fails, report
the coverage failure rather than relax the gate or call another mechanism an
untouched replacement test.

The future model comparison is fixed to the unchanged original step-2742 adapter
and the candidate selected by the existing v2 pilot's frozen phone-development
rule. Transfer results may not select an alternate checkpoint. Compare direct
choice, direct choice with publicly provable cost-dominated plans excluded, and
predicted continuation-success probability minus known call costs. Report the
fixed stop, cheapest-completion and longest-completion rules alongside them.
The latter controller diagnostics were motivated by exposed phone development
results; they are fixed before any reserved task is executed here.

Report decision return and regret, continued-success probability scores, coverage
and per-program outcomes. The prospective joint transfer check is at least 0.03
higher direct-choice mean return and at least 0.02 lower continued-success expected
Brier score versus the original, with the pilot's general-retention checks intact.
Controller improvements remain separate from model improvements. Compare absolute
performance with the strongest fixed heuristic; passing a relative gain from a
weak original does not by itself justify scaling. Four to seven programs would
still be a small transfer pilot, not proof of generality or Jev parity.

Protected tasks, solutions, derived traces and future predictions stay private.
Publish only generic code, aggregate counts, hashes and limitations. Separate new
task instances, reference/control executions, future alternative branches, question
variants and actual learning consumption. This stage consumes zero training data.
